# AutoWave — AGENTS.md (rules for Codex)

You are the implementation engineer for AutoWave, an iOS rhythm game that converts
user-provided audio into playable beatmaps. Claude (the orchestrator) hands you one
scoped task at a time; your job is to write the code and files for that task only.

## Hard rules

- Implement exactly the task you were given. No scope creep, no drive-by refactors.
- **Never run git commands.** You edit the working tree; the orchestrator reviews,
  builds, and commits.
- Never touch `refs/` (local-only reference images) or `docs/plans/` history.
- No third-party dependencies (SPM/CocoaPods) unless the task explicitly grants one.
- If a task is ambiguous or conflicts with these rules, stop and say so in your
  final message instead of guessing silently.

## Toolchain & project structure

- Xcode 26.6 / Swift 6 / iOS deployment target 17.0. SwiftUI app shell; the
  gameplay scene is SpriteKit. Persistence is SwiftData; audio is
  AVFoundation/AVAudioEngine; DSP is Accelerate (vDSP).
- The Xcode project is generated by **XcodeGen** from `project.yml`. When you add,
  remove, or rename source files: update `project.yml` if needed (folder-reference
  globs usually cover it), then run `xcodegen generate` so `AutoWave.xcodeproj`
  stays in sync. Both `project.yml` and the generated project are tracked.
- Build verification command (the orchestrator also runs this as a gate):

```bash
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project AutoWave.xcodeproj -scheme AutoWave \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

## Source layout

```
AutoWave/
  App/            # @main, root navigation, app-level state
  Features/
    Library/      # saved tracks & beatmaps (SwiftData-backed list)
    Import/       # local audio file ingestion (fileImporter / MPMediaPicker)
    Analysis/     # conversion screen: progress UI over BeatmapKit pipeline
    Gameplay/     # SpriteKit scene, input, scoring, results
  Core/
    Models/       # Track, Beatmap, Note, ScoreRecord (Codable + SwiftData)
    BeatmapKit/   # deterministic audio-analysis → beatmap pipeline (pure Swift)
    AudioEngine/  # playback + realtime FFT tap for the visualizer background
  Resources/      # assets, localized strings (Korean-first)
AutoWaveTests/    # unit tests (BeatmapKit determinism, scoring rules)
```

## Domain rules

- Difficulties, exact order and naming: 천국 (Heaven), 쉬움 (Easy), 보통 (Normal),
  어려움 (Hard), 지옥 (Hell). Difficulty is a parameter set over one shared
  analysis result — never re-analyze audio per difficulty.
- `BeatmapKit` must be deterministic: same audio + same difficulty + same seed ⇒
  identical beatmap. Keep it free of UIKit/SwiftUI/SpriteKit imports.
- Note types: `tap` (single hit) and `drag` (hold ribbon; may be straight or move
  laterally). Breaking a drag mid-way deactivates the remainder of that ribbon:
  greyed out, no further score ticks.
- Visual identity: the "wave ripple" note design described in the plan — do not
  imitate capsule/arrow note styles from existing rhythm games.
- YouTube ingestion is out of scope. Local audio files only.
- User-facing strings in Korean; code identifiers, comments, and commit-facing
  text in English.

## Quality bar

- Code must compile with zero warnings introduced by your change where practical.
- Prefer value types and pure functions in `Core/`; keep view code thin.
- Write/extend unit tests when the task touches `BeatmapKit` or scoring logic.
- Match surrounding code style; no decorative comments.
